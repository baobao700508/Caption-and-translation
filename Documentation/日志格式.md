# 课堂日志读取契约

`speaker_id` 保存百炼实际返回的说话人编号：`input_audio_buffer.speech_started` 记录原始分配，明确关联的 `provider.segment_link`、`text.append` 和 `text.replace` 沿用该原文组的编号。它也保存在 Transcript 的 Segment 中。编号 0 有效；未返回时不补造编号。统计人数必须使用同一 `connection_epoch` 内不同编号的集合，不能把开口次数、服务组数、不同连接里的相同数字或音色变化当作人数。

`provider.configuration` 对每次 `session.updated` 保存 `requested_turn_detection`、`server_turn_detection`、确认来源及匹配结果；同传另行记录 `voice_clone_requested=false`、服务确认的克隆关闭状态及默认 `Tina` 音色；停用复刻时不虚报复刻频率。服务回显与请求不符时记录 `provider.configuration_rejected`，随后连接失败，不静默回退为另一种检测方式。回显说明可观测的会话配置，不是对服务内部实现的审计。

默认根目录是 `~/Documents/LiveCaption Logs`，可通过应用中的“日志目录”或桌面配置更改。记录在会话运行中持续更新，收起字幕窗口不会停止写入。文件只保存在本机，AI 需要具备相应目录的读取权限。

## 读取入口

先读取根目录的 `latest.json`，按其 `live` 相对路径读取最近内容，需要完整上下文时读取 `transcript`。索引提供 `session_id`、`active`、`state`、`updated_at`、`written_sequence` 和 `snapshot_sequence`。检查会话与更新时间后再解释记录；`active: true` 表示会话未结束，不能单独证明最近一直有声音或文字。

`live.md` 和 `transcript.md` 都含状态、快照序号、最近文字时间与连接缺口。`live.md` 按语段最后接收时间保留最近十分钟，跨越窗口的完整语段可能包含更早的文字，不是按每个词的音频时间精确截取。整场历史保留在 `transcript.md` 和 `events.jsonl`。

```python
from pathlib import Path
import json

root = Path.home() / "Documents/LiveCaption Logs"
index = json.loads((root / "latest.json").read_text())
document = (root / index["live"]).resolve()
document.relative_to(root.resolve())
text = document.read_text()
print(index["session_id"], index["updated_at"], index["active"])
print(text)
```

Markdown 文件以原子替换方式更新，通常在文字事件后约 300 ms 生成快照。多个文件不构成一个文件系统事务；会话切换或并发更新时，以正文里的会话和快照序号核对索引，必要时重新读取。两秒健康刷新会同步日志；这些调度间隔不是所有负载下的延迟保证。

## JSONL 事件

`events.jsonl` 每行是独立 JSON 对象，追加写入。课堂尚未定稿时，临时文字也会入文件。外部读取者遇到写入中的半行应保留等待下一次读取，不把半行解释为事件。

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 当前为 1 |
| `session_id` / `sequence` | 用户会话和单调递增的事件序号 |
| `connection_epoch` | 云连接尝试代次；更换模型、恢复或轮换时递增 |
| `event_type` | 文字追加、替换、段落关闭、状态、缺口或其他事件 |
| `received_at` | 本地接收 UTC 时间，毫秒精度；不是词级音频时间 |
| `provider` / `model` / `pipeline` / `mode` | 该事件所属连接的供应商、模型、线路与输出模式 |
| `track` | 文字事件的 `source` 或 `translation` |
| `provider_segment_id` | 百炼原始消息标识（译文带内容索引），可选；不保证原文与译文一一配对 |
| `segment_id` / `revision` | 语段标识及其修订版本 |
| `text` | 本次追加片段或替换后的整段文字 |
| `finality` | `interim`、`final`、`unconfirmed` 或 `unspecified` |
| `audio_start_ms` / `audio_end_ms` | 可靠供应商 offset，未提供时为 `null` |
| `time_origin` | `local_receive` 或 `provider_audio` |

`text.replace` 按同一 `segment_id` 覆盖文字；`text.append` 才进行追加。不能把每次 interim 作为新句拼接。Transcribe 的 final 替换当前 interim 并关闭语段。百炼 Translate 的原文和译文独立按云消息 ID 聚合；delta 追加、completed／done 的整段文字覆盖同段。译文须等 `response.done.status == completed` 才标 `final`，不完整响应为 `unconfirmed`；空白最终修订可清除临时文字。Google Translate 两条轨独立追加，没有明确 final 时保留 `unspecified`。停止或断线时未确认的 interim 会标为 `unconfirmed`。

`gap` 代表缺口或无法确认的发送情况；`input.changed`、`pipeline.changed` 和连接事件标明上下文边界。切换失败可能出现更大的连接尝试编号，但 `session.json` 的 `active_connection_epoch` 仍指向继续工作的旧连接。百炼收到 `session.finished` 才能确认尾部处理完毕；收尾超时、断开或旧连接未完整收尾时，`session.stopped.tail_incomplete: true` 表示无法确认所有已发送音频均已被服务端处理，不能据此断言文字覆盖整段音频。

`input.discarded` 给出丢弃原因、`sample_count`、`capture_started_at`、`capture_ended_at` 和 `replayed: false`；重连后只保留新声音，不把缺口补成静音或上传旧包。`input.reconnected.accept_capture_from` 是恢复切点。第一包新声音成功发送后，Markdown 缺口摘要显示这次未发送音频的丢弃时长；这不包含断线前已提交但送达状态未知的尾段。

`connection.final_finish.confirmed` 单独描述最后连接是否正常结束。Google Transcribe 的 `provider.google_input_finalized` 记录正式末段确认，`provider.google_input_unconfirmed` 表示等待超时或仍有临时结果。它们都不提供逐采样点的服务器接收证明。

文字日志不含 API key、恢复句柄或音频负载；录音以独立 WAV 文件保存在同一会话的 `audio/` 中。`playback.scheduled`、`playback.completed` 和 `playback.cleared` 仅记录播放状态。日志文件不会自动交给其他应用；启用字幕智能分段时，会把待整理文字发送给配置中的文字模型服务。

## 派生字幕排版

启用字幕智能分段后，模型成功整理的最新显示内容会原子写入同一会话的 `caption-layout.json`。字段包括 `session_id`、`connection_epoch`、`updated_at`、`model`、`derived_presentation: true` 和 `rows`；每行包含原始文字切片 `source` 与 `translation`，不会将模型改写的文字写入正文。

这份文件是最新连接代次的排版快照，可能滞后于实时文字或在服务端修订后等待下一次整理，不是整场记录，也不提供词级时间对齐。AI 追课应以 `live.md`、`transcript.md` 和修订事件为准；需要参考屏幕分组时，再结合排版快照的会话、连接代次和更新时间。重排不会延迟、替换或删改这些原始日志。

`caption.layout.applied` 记录重排模型、请求耗时、尝试次数、显示组数、`row_ids` 和 `unique_row_ids`。`caption.reflow.validated` 保存新段 `id` 及 `retained_row_ids`，可检查前段保留与末段接续是否错误复用身份。`caption.reflow.discarded.reason=duplicate_view_row_ids` 表示派生排版被拒绝并回退原始字幕。显示标识按每次任务独立生成，取消代次不作为显示身份。`caption.first_projected.projection_ms` 只测收到该消息后更新 AppSession 字幕状态所花的本机时间，不能当作说话到字幕出现的延迟。停止时先处理供应商末段，在有界等待内完成最后的分段与审计写入，再关闭会话日志；超过等待上限的任务明确取消，不能在关闭后冒充已应用。

`scripts/analyze-caption-latency.py 会话目录 --output 输出.json` 将上传索引、原生输入队列、初始 RTP 包时钟、服务 VAD／定稿事件和分段判断耗时分开统计。服务 `audio_start_ms`／`audio_end_ms` 相对音频流起点，不能直接相减于晚于媒体轨启动的麦克风首帧；重连后重新校准对应代次。输出的服务事件滞后不是每个词的字幕延迟，也不能单独判定服务内部和网络传输的责任。

`first_text_events` 另按连接代次、轨道和消息项记录服务语段起点到首条非空文字日志的估算间隔；后续增量和定稿不覆盖首次时间。计算先假定每 RTP 包代表 20 ms 声音，以本机统计记录时间减包数时长估计音频流零点，再加服务 `audio_start_ms`。该换算依赖双方音频零点对应，不能仅凭发包稳定证明对应正确；服务字段是音频位置，不是服务端收包、处理或发包的时刻。`maximum_first_text_delay_seconds` 与 `maximum_provider_event_lag_seconds` 分别检查，不能用及时返回的 VAD 事件替代文字时效。真人文件验收的两项门槛均为 5 秒，缺少测量值或任何一项超限均失败；`verify-human-app.sh` 将 `first_text_latency_pass` 和 `provider_event_latency_pass` 一起计入总结果，主动断线验收也不能覆盖这些失败。这些五秒门槛是脚本辅助诊断门槛，不是实际同传延迟验收。服务语段起点不保证精确对应首词发音，首条文字也可能只是一个字或多个词；它不测完整意思何时翻译出来，更不测何时听见译音。

`session.started` 保存运行包的 `app_version` 和 `app_build`。`bailian_turn_detection_policy` 是配置策略，`bailian_turn_detection` 是按当前输出模式解析的实际方式；默认 `auto` 在纯字幕和带译音模式均选择 `server_vad`。`provider.configuration` 保存服务回显的实际方式及本机策略，两者必须符合当前输出模式；服务不会收到 `auto` 字符串。

`transport.webrtc_delivery` 保存原生 DataChannel 回调入口的本机时间与进入 Swift 接收循环时的排队时间；排队时长使用单调时钟。常规采样最多每秒一条，排队超过 250 ms 立即记录。`native_receive_queue_max_seconds` 是该排队时长的最大观测值，不能当作云端语音处理或物理屏幕延迟。原生统计同时保留 `totalPacketSendDelay`、`totalSamplesDuration`、`jitter` 等数值；`totalPacketSendDelay` 是累积量，不能直接当作某个包的最大延迟。

同一长音频的实时文字进度由 `scripts/compare-caption-progress.py 会话目录 健康参考会话 --output 输出.json` 比较。它核验两份上传 PCM 的采样格式和 SHA256，按至少四个连续匹配原文词比较首次 interim 到达时刻；最终全文修订保留未改变字符的首次到达时间。有原生消费计数时，以最初五秒的 `consumed_samples`、`underflow_samples` 与 `tail_padding_samples` 校准首个 PCM 样本的时钟，剔除 RTP 已运行而麦克风尚未开始的启动静音；初始时钟分散超过 250 ms 拒绝比较。旧日志没有消费计数时回退初始 RTP 时钟，并在结果中标明依据。输出包含双方时钟、匹配覆盖率、额外延迟 p95／最大值与末四分之一相对首四分之一的中位变化。不同音频、断线多代次、参考收尾未确认或参考事件滞后超限均不能通过。该结果是相对参考的原文进度，不是逐词音频强制对齐，也不代表翻译准确率；参考的首批文字预算仍需单独验收。`LIVECAPTION_LATENCY_REFERENCE` 可让真人文件验证一并执行此检查，保存 `source-progress.json` 并将失败计入总结果。

有原始参考文本和精确片段结束时间的真人录音，可用 `scripts/analyze-caption-checkpoints.py 会话目录 provenance.json --output 输出.json` 检查绝对句尾滞后。参考 PCM 的 SHA256 必须匹配，原文末尾四个词连续匹配且必须包含该片段最后一个词；不能用附近更早的词代替。至少覆盖 60% 片段，并同时覆盖首、末四分之一，才能判断增长；末四分之一相对首四分之一的中位滞后增长不得超过两秒，已测句尾滞后最大值和 p95 不得超过五秒。没有足够参考时报告不足，不能让几轮同样迟到的字幕互相比较后冒充没有累积。片段尾部可能含自然静音，负值表示末词在片段文件结束前已经出现，不强制截为零；这个测量不等于逐词语音对齐。

带译音测试还须单独读取 `transport.webrtc_stage` 的 `playout.draining`、`playout.drained`、`playout.timeout` 和 `drain_wait_ms`。`drain_wait_ms` 测服务端会话完成通知到原生解码译音排空确认的等待；结合首个消费样本时钟和输入时长，另算输入结束到排空确认的等待。后者含排空确认保护时间，不代表最后一个词的实际发音时刻。纯文件验收不播放物理扬声器，所以这些时间也不是听者端声学延迟。文字及时、输入完整、没有断线和收到末段确认，均不能单独证明译音没有积压。

JEV 的完整判断另存为同目录下可实时追读的 `reflow-decisions.jsonl`。`caption.reflow.request` 包含阶段及完整 `state`、`questions`、所有 `criteria` 选项；`response` 保存每题全部概率分布、评分、置信度、实际模型、用量和耗时。`alignments` 记录对应位置的采用／拒绝，`selection` 记录实际候选块、各项检查值、最终路径、每块是否被选中及原因。`started` 标明 `trigger_reason`、`job_id` 和尝试次数；修订失效、超时、失败及预算保留均有事件。

`caption.presentation.changed` 记录显示结构变化：`display_policy=single_open_tail` 表示启用整理时将未整理服务组连续显示在一个尾段；`provider_groups` 表示关闭整理后的服务组显示。事件包含内部 `provider_group_ids`／`provider_group_count`、可见 `row_ids`／`display_row_count` 和 `byte_identical`。模型结果之外的连续追加不新增显示边界；模型最后一块承接新文字。仅正文增长且组与显示身份未变时不重复记录该结构事件，原始文字事件仍完整记录。

详细日志的 `trace_sequence` 在 `events.jsonl` 的同名事件中有索引。两份文件分别追加，不构成文件系统事务，读取时按 `session_id`、`job_id`、`attempt`、`stage` 和序号关联；遇到半行等待下一次读取。JEV 双语正常每批两次请求，纯转写跳过对应阶段，重试可能增加调用次数。概率、Score 等级和 `confidence` 是模型判断，不构成语义已被证实的证明。日志包含与课堂记录相同的正文隐私，但不保存 API Key、HTTP 鉴权头或私有配置文件。

## 连续译音与实际声音位置

测试进程启用 `LIVECAPTION_AUDIO_TIMELINE_PROBE=1` 后，`audio/probe-decoded-output.wav` 保存每个 10 ms 原生解码输出块，包含长静音；普通运行不创建这条轨。`probe-decoded-output-index.jsonl` 保存输出块的 `sample_offset`、`sample_count`、`sample_rate`、`connection_epoch`、`callback_at_unix_seconds` 与 `callback_uptime_seconds`。`probe-input-index.jsonl` 对既有 `webrtc-input-observed.wav` 的有效输入样本建立同样的实际回调索引。原始 `translated.wav` 会省去较长的数字静音，不能直接用文件位置代表连续墙钟时间。

这些时间位于本机编码器输入回调和本机解码输出回调，不是服务端内部时钟，也不是物理扬声器发声。以实际录音中的声音位置查索引，再在同一个本机时钟上相减，避免用 RTP 包数估计零点。跨连接的回调间隙必须保留，不能靠拼接 WAV 抹去。

静音追赶测试将两段可追溯的真人录音之间插入明确时长的数字静音，保留同一连接，比较前段原音／译音末尾与静音后新段原音／译音开头。必须确认旧译音已经排空、新声音与新段内容相符。输出静音保留在连续轨中，声音门槛变化须做敏感性检查。

长录音的内容终点对照先按服务关联组取得英语与中文文字，再分别在真实英语和译音录音中用本地离线识别的词时间戳定位末尾连续内容；唯一匹配不足时记为缺失，不当作零延迟。两个声音终点查实际回调索引后相减，是完整关联组结束的译音滞后估算，不能当作每个词都对齐或翻译质量已经验证。报告须同时提供匹配数量、覆盖、原译内容、首末时间范围与可回听证据。

测试开关还采集 `inbound-rtp` 的接收缓冲统计。相邻采样的 `jitterBufferDelay` 增量除以 `jitterBufferEmittedCount` 增量，才是这段时间已释放样本的平均缓冲停留；累计值不能直接当作单个包的延迟。`insertedSamplesForDeceleration` 和 `removedSamplesForAcceleration` 表示为减速／加速播放插入／移除的采样数，不是服务端为了翻译准确率等待的证据。[W3C 定义](https://www.w3.org/TR/webrtc-stats/)。

`connection.rotation_policy` 记录自动轮换策略。百炼当前为 `scheduled:false`，不按九分钟主动重建；Google 保留既有策略。未公开明确的 LiveTranslate 连接墙钟上限，不能把 Omni 的时限或上下文 token 数套用为课堂总时长。

## 录音回听与音频证据

每次新会话自动保存 `audio/uploaded.wav`（16 kHz、单声道、PCM16）。它直接拼接客户端 `sendAudio` 成功返回的原始字节，不经过二次降噪、增益或编码。客户端发送成功不等于服务端已确认消费；发送失败的包不进入该文件，但仍可能已经到达服务端。`upload-index.jsonl` 记录每包的连接代次、文件样本偏移、样本数和本地发送起止时间。断线与休眠期间不向上传轨插入静音，需结合索引和 `events.jsonl` 判断实际缺口。

启用系统声时另存 `system-before-ns.wav`，启用麦克风时另存 `microphone-input.wav`，均为 48 kHz 单声道 PCM16。这两条轨来自按 host time 对齐、重采样后的输入时间轴，在分路 WebRTC NS、混音增益及最终 16 kHz 转换前保存；并非设备原始多声道数据。麦克风对比轨可能已经经过 Apple Voice Processing，不代表关闭全部处理的物理麦克风原音；时间轴缺失窗口仍为填补的静音。`audio.processing` 记录当时处理配置。麦克风另存 `microphone-captured.wav`，为采集块直接重采样到 48 kHz 后的连续轨，在时间轴对齐、填静音前写入；它仍位于 Apple Voice Processing 后，可与对齐后输入及上传轨分别比较，不能把它当作未经过 Apple 处理的物理原音。

`recording.json` 提供各轨采样率、写入样本数、时长和是否正常结束。`encoder_epochs` 另外按连接代次给出编码器观察轨的 `sample_offset` 与 `sample_count`，用于区分已提交 PCM 和断开时尚未进入观察轨的尾段；这些样本不跨连接重放。录音按约 100 ms 批次写入并更新 WAV 文件头，两秒健康检查同步文件；突然崩溃或断电仍可能损失最后一小段。异步磁盘队列有上限，录音写入错误会停止采集并给出错误。WAV 单文件采用 RIFF 32 位长度上限，达到上限时停止并提示开始新会话。

在“设置 → 记录与连接 → 录音回听”选择播放上传轨或输入对比轨，或打开录音文件夹。录制中提供“结束记录并回听上传音频”，避免回听声被再次采集。可选择历史会话中的 `audio/uploaded.wav` 回听；新版安装前未保存的音频无法补录。录音只保存在用户选择的本机日志目录；上传轨约 115 MB／小时，每条对比轨约 346 MB／小时；麦克风开启时保存对齐前和对齐后两条对比轨。

## AI 追课提示

读取 `latest.json` 指向的 `live.md`，必要时读取 `transcript.md`。说明刚才讲了什么、关键术语、当前正在讨论的问题，帮助接上课堂。注明记录更新时间、仍在识别的内容和已标记的缺口；不要把识别假设当成教师确认的事实。
