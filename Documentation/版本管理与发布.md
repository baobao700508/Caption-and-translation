# 版本管理与发布

桌面 `LiveCaption.app` 是唯一日常入口，固定指向主工程的 `dist/LiveCaption.app`。SaT、WhisperKit、Google 和百炼属于同一个应用的可选功能，不各自发布桌面版本。

## 源码与版本

主工程 `Sources/`、`Tests/`、`Resources/` 和 `scripts/` 是合并后的源码。`Experiments/` 内的工作副本用于验证，不能直接替换正式应用。

版本只在 `Resources/Info.plist` 定义。`CFBundleShortVersionString` 表示应用版本，`CFBundleVersion` 使用递增整数。正式发布不得使用 `15.1` 一类独立追加的构建号，也不能把较旧工作副本的版本覆盖到正式包。

实际发布记录保存在 `Releases/current.json`，包括版本、构建号、可执行文件 SHA-256、源文件清单、检查结果和旧包归档位置。界面“关于”显示的版本、当前可执行文件校验值、源码版本与该记录应一致。源码修改后，已运行的进程仍使用原程序；发布不会自动把旧进程变成新版本。

## 发布

退出现有 LiveCaption 后，在主工程执行：

```bash
bash scripts/build.sh --activate --archive-legacy
```

此入口调用 `scripts/release.py`，同一时间只允许一个发布任务。它先运行主工程检查，在独立暂存目录构建并验证签名，再用同一可执行文件执行原生界面检查。构建期间源文件发生变化、检查失败、构建号未递增或仍有旧实例运行时，不发布新包。

验证通过后，旧正式包移入 `Releases/Archive/`，暂存包放到唯一正式路径，桌面快捷方式恢复为该路径。`--activate` 从桌面入口打开程序并确认新进程路径；`--archive-legacy` 同时归档 `dist/` 内的其他旧应用包。归档保留回退所需文件，不删除历史录音、日志和测试证据。

检查、界面结果和源文件清单保存在 `TestResults/release-版本-构建号-时间/`。这些检查验证合并后的程序和界面，不代表重新测量了云端延迟或整节课稳定性。

## 独立开发

并行开发先合并到主工程，再统一发布。需要构建隔离验证包时，为 `scripts/build.sh` 显式设置 `LIVECAPTION_APP_PATH`，输出到自己的实验目录；不得指向 `dist/LiveCaption.app`，也不得改桌面入口。独立验证包只在测试期间运行，不能另设正式版本号或抢占用户日常入口。
