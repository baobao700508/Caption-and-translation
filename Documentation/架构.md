# 架构与职责

应用由 `LiveCaptionApp`、`LiveCaptionCore` 和原生音频桥接组成。SwiftPM 编译目标与对外类型保持独立；目标内的子目录用于职责归类，不引入新的运行层级。

## 应用协调

`LiveCaptionApp/Session/AppSession.swift` 保有当前配置、会话、采集、连接、字幕及窗口状态。方法在同一文件中按电源状态、配置、录制发送、云事件、字幕设置、线路切换、恢复健康检查、收尾日志分组。存储属性和初始化顺序保留在主声明中，方法扩展共享原来的 `private` 范围。

- `Configuration/` 管理 Keychain、设置文件串行写入与本地模型准备状态。`LocalModelManager` 协调按需安装、取消、进度、验证结果与安装日志，不拥有录音生命周期。
- `Audio/` 区分设备属性、系统进程采集、前处理与硬件播放。实时回调不执行文件、网络或模型工作。
- `Presentation/` 管理字幕、浮窗、迷你条、共享控件及滚动；`Preferences/` 管理完整设置与 SaT 参数。
- `Verification/` 保留应用内验证入口，复用生产发送、连接、字幕和日志路径，不代替物理设备验证。

## 核心处理

- `Configuration/` 包含配置类型、兼容读取、供应商选择及校验。
- `Providers/` 将百炼消息解析与连接生命周期分离，保留 Google、WhisperKit 和 WebRTC 适配器。
- `Networking/` 包含既有 `RealtimeTransport` 接口、WebSocket 及单次写入完成保护。供应商协议不拥有传输实现。
- `Captions/` 包含原译文关联、保真文字片、SaT 判断和显示协调。关闭整理时返回服务组，开启时处理连续定稿前缀。
- `Logging/` 管理会话事件、录音、连接归档与崩溃恢复；`Audio/` 管理队列、音频时间轴及本机播放追赶。

`SaTLocalRuntime.swift` 保留在核心目标根层，维持开发态 `#filePath` 相对脚本定位的目录深度。打包应用优先使用 Resources 中的 worker；命令行核心检查可使用工程内脚本。worker 的队列、取消、超时和输入输出协议保持原有实现。

## 本地模型准备

`LocalModelFiles` 统一管理用户数据目录、完整性记录和 Whisper 准备入口；`SaTModelPreparation` 在后台运行 App 与开发者共用的安装脚本，取消时终止安装进程。界面只调用这两个入口，不拼接下载地址、不安装系统依赖。

- SaT 先下载固定版本、对应处理器架构的独立 Python，校验 SHA-256，再按固定依赖清单安装到独立运行环境。模型与分词器使用固定仓库修订和文件哈希，下载到临时文件，校验后替换，实际离线推理成功后写完成记录。
- Whisper 通过当前固定版本的 WhisperKit 下载 Core ML 模型及分词器，并执行本机模型加载和识别检查。完成记录保存必需文件清单与尺寸；文件缺失或截断时不允许开始本机识别。
- 下载与安装均由用户在“本地模型”明确启动；新建配置不触发模型下载或采音。SaT 推理使用本地文件且禁止联网下载；Whisper 在会话日志和采集开始前检查准备状态。
- App 包内仅携带安装清单、脚本和原生引擎，模型、Python、依赖及日志位于用户的 `Application Support/LiveCaption`。源码仓库不跟踪这些下载内容。`develop.sh` 为干净源码准备构建依赖，`LiveCaptionModelSetup` 供开发者独立准备 Whisper。

## 原生桥接

`AudioBridge` 保留 C 原子环形缓冲与 C++ 降噪处理，`WebRTCBridge` 保留原生音频设备和媒体传输。两者桥接源码逐字节保持；可选 `AoqBridge` 仍仅供传输实验使用。

## 验证约束

`verify-source-refactor.py` 用于 `v0.1.19-build23` 的结构重构验收，使用 SwiftParser／SwiftSyntax 比较基线与该版本的声明 token，并检查 AppSession 存储属性顺序、原生桥接和既有测试。它不用于要求后续新增功能与旧基线的函数体相同。

核心检查覆盖协议、音频队列、文字修订、跨连接归属、收尾、日志恢复、SaT 和播放追赶。原生界面检查覆盖三种模式、浮窗、隐藏恢复、穿透、自动保存和本机转写选择。真实文件输入测试另外覆盖生产会话、云端文字及译音、输入保真、整理开关和服务端收尾。
