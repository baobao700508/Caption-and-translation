# LiveCaption

本项目是独立的 macOS 原生课堂字幕工具工程。当前使用与开发入口见仓库根目录 README，源码结构见本目录的架构说明；历史调研按其对应版本解释。

- Swift 原生菜单栏、非激活字幕浮窗；Translate 默认使用百炼 Qwen3.8 LiveTranslate，支持服务端纯文字与文字＋语音模态；Transcribe 可选 Google 在线或 WhisperKit 本地原文识别。供应商凭据分别保存，不能互相回退。
- 日志是核心功能，必须在会话运行时可被外部读取。保留 interim/final、修订、缺口与连接代次，不能把临时文字重复追加为新句。
- 麦克风 Apple Voice Processing 与系统 WebRTC NS 分路处理，不叠加降噪器。
- 桌面配置含用户凭据，不能提交、打印或带入测试报告。文字日志不得存 key、恢复句柄或音频负载；用户已授权录音，独立保存到会话 audio/ 下的 WAV，上传轨必须与成功发送的 PCM 字节一致，并保留发送确认的证据边界。
- 使用项目内脚本构建和验证；实时模型、真实采集、扬声器回授与离线协议测试分别报告，不混称端到端成功。

## 术语表

| 术语 | 含义 |
| --- | --- |
| 用户会话 | 一次开始至停止；连接轮换不改变 session_id |
| connection_epoch | 云连接或本地识别器实例的代次，模型切换或重连时递增 |
| speaker_id | 服务端返回的说话人编号，仅按 connection_epoch 内的编号统计；0 也有效，缺失保留为空。编号变化是服务分配变化，不直接等同于真实换人或音色复刻变化 |
| Translate | 直接语音翻译线路；同传播放译音，同译仅显示字幕 |
| Transcribe | 独立的原文识别线路，原文字幕与日志，无翻译 |
| Whisper 本地 | WhisperKit 驱动的本机原文转写；消费现有 16 kHz 单声道 PCM，以 Core ML 的 CPU/GPU 计算，不另开采音设备 |
| 本地模型准备 | 首次下载、加载及预热，完成后才开始采音；与录音中的字幕出现等待分别计时 |
| 本地滚动窗口 | 单个推理任务读取最新音频，保留未定稿尾部；不为每包声音排一个推理任务，不把上下文窗口长度当作实际字幕延迟 |
| interim / final | 可修订识别假设 / 供应商确认的识别结果，不表示事实已核实 |
| live.md | 最近十分钟可读快照；完整历史仍保留 |
| CaptionParagraph | 原译文显示容器；内部服务组只按明确关联配对，启用整理后界面显示模型阅读块与待整理尾段，正文完整保留在 Transcript 与日志中 |
| 待整理尾段 | SaT 尚未固定的连续文字；临时结果立即显示，定稿后在本机整理 |
| 固定段落 | SaT 已选出的段落；后文接在尾部，供应商改字时保留不受影响的前缀，重新处理受影响范围 |
| CaptionReflow | 仅使用 SaT 本地段落检测的派生排版；先显示与记录，再选择原文字片切点，不改写正文。关闭时原样显示服务端 VAD 语段及明确关联的译文 |
| 字幕显示标识 | SwiftUI 段落身份；已固定前段保持原标识，新整理结果按 job_id 生成新标识，同一屏幕投影内必须唯一，不能复用连接或取消代次作为任务身份 |
| 界面心跳 | 主线程周期执行的响应证据；外部进程检查超时并保存进程采样，不代表语音识别或翻译延迟 |
| 服务语段起点至首条文字的估算间隔 | 按假定每 RTP 包 20 ms 倒推的本机音频流零点，加服务 audio_start_ms，再减于本机首条非空文字日志时间；依赖双方音频零点对应的假设，只作辅助诊断，不能当作已验证的实际翻译延迟 |
| 录音句尾检查点 | 已知真人录音片段结束至对应原文末尾四词首次到达的时间；用于独立检查字幕滞后是否随播放增长，参考缺失或覆盖不足不能判通过 |
| 译音尾部等待 | 服务端完成通知后原生解码译音继续排空的时间；另记录输入结束至排空确认，不能当作逐句译音或物理扬声器延迟 |
| 译音数据返回间隔 | 在实际输入和实际收到的译音中分别定位同一服务明确关联组的尾部声音；WebRTC 以包含中文尾音的原始 RTP 实际入站处理时刻减包含英语尾音的 PCM 实际交给编码器时刻，WebSocket 单独使用其写入与 PCM 消息接收边界，两种传输结果不可互代；不使用播放或解码回调充当收包时间，未定位或尾部未到齐不能判零延迟 |
| 同组中文字尾到达间隔 | 同一明确关联组的最后中文汉字及其结尾上下文实际经 DataChannel 收到的时刻，减对应英语尾音 PCM 交给编码器的时刻；另存完整最终文字首次具备时间。原文未完整定稿的已识别句子只作异常内容检查点，不混入完整组尾统计 |
| 连续译音时间轴 | 测试开关启用时保存每个 10 ms 本机原生解码输出块，包括静音，并以实际回调时间和样本偏移建立索引；不靠音频包数倒推时刻，不代表物理扬声器发声 |
| 静音追赶测试 | 两段真人录音中间输入明确时长的数字静音，在同一连接中比较第一段末尾到译音末尾的间隔，以及第二段开口到新译音开口的间隔；须确认旧译音已排空且新声音内容相符 |
| 本地播放追赶 | 只对已经收到并原样归档的中文 PCM 副本做保音调变速；按尚未播放完的至多 100 ms PCM 块计待播媒体时长，以双水位和平滑速度追赶，不改动云端到达时间、不静默跳过译音。该计数含渲染管线，不是物理扬声器精确延迟 |
| 译音内容终点对照 | 在原始英语和实际译音中分别定位同一服务关联组的末尾内容，以声音位置映射到实际本机回调时间后相减；离线识别时间戳存在误差，不能当作每个词都经过人工核验 |
| 云端语段检测策略 | 建连时选择的语音处理方式；auto 在书面同译和带译音同传均解析为 server_vad；显示阅读块由 CaptionReflow 决定 |
| SaT 本地段落整理 | 独立本地 ONNX 文字后处理；draft 先连续显示，仅消费连续 final 前缀，分批处理并保留上下文。双语只在明确关联服务组之间选边界，不按字数比例或到达顺序配对；识别、翻译、译音播放不经过 SaT |
| reflow-decisions.jsonl | SaT 本机推理输入、段落概率、采用边界、参数和取消行为的审计日志；不保存凭据 |
| 恢复切点 | 新连接完成配置的本机时间；采集开始早于切点的包全部丢弃，不能补传或跨连接重放 |
| 收尾确认 | 连接适配器按供应商协议及日志中明确的证据范围完成尾部处理；百炼等待服务结束通知，Google 原文转写也允许已有定稿在有界接收等待后按 received_transcripts 范围完成。它不是服务器逐采样点或每个结束请求的收货回执；已发生的断线缺口独立保留 |

- 百炼 `provider_segment_id` 是原始云消息标识；不能推定 source 与 translation 的消息 ID 一一配对。
- 百炼开口事件中的 `speaker_id` 必须保留到诊断、明确关联的原文／译文 TextUpdate、Segment 和文字日志；不得把语段数量当说话人人数。每次 `session.updated` 都验证所请求的检测方式并记录服务回显，发生不匹配记录 `provider.configuration_rejected` 并拒绝，不自动改为另一种检测方式。声音复刻频率与 Speaker 编号分开解释，音色变化本身不是后台切换检测器的证据。
- 百炼 `session.finished` 是停止后的尾部完成确认；`response.done` 只完成一个响应，不能结束整个会话。
- 同声传译关闭声音复刻：请求 `enable_voice_clone=false`、默认音色 `Tina`，不提交 `voice_clone_options`。服务回显必须确认克隆关闭及该音色；不符则停止发送，不能静默接受克隆。书面同译仍不提交任何音色／复刻设置。
- WhisperKit 仅由 `transcribeProvider=whisperKit` 选择，旧配置仍使用 Google。默认模型为 `openai_whisper-large-v3-v20240930_turbo`，Core ML 三个组件均设为 `cpuAndGPU`；执行计划与实机 GPU 利用率采样是不同证据。通过设置中“本地模型”的下载与验证后才开始采音，后续同进程会话独占复用已加载模型。
- 本地识别同时只运行一次推理，默认每新增 0.8 秒音频更新；窗口最多 24 秒，缓存超过 32 秒明确报错并停止，不无限重连。临时空假设保留已有文字，持续无文字噪声到窗口上限须推进。关闭温度回退重试时，必须同时禁用 `firstTokenLogProbThreshold` 提前退出，否则唯一一次解码可能在首个预测处终止而返回空文字。`local.whisper.*` 日志记录加载、每轮音频范围、推理耗时、窗口推进理由、错误与收尾。识别音频留在本机；字幕整理只使用本机 SaT，不调用在线整理服务。
- Google Transcribe 使用 `audioStreamEnd` 推动末段定稿，最多等待十秒。`inputTranscription` 定稿对应讲话段，不对应每个麦克风音频包；已定稿之后继续上传的安静声音不一定触发新文字。停止后的有界接收等待结束时，若已有正式定稿、没有后续未定稿文字且连接未失败，可按 `received_transcripts` 范围完成本地收尾；日志记录依据、最后定稿时的包数和等待时长，不虚构服务端逐包或结束信号回执。后续 interim、连接失败、取消及完全未收到识别结果仍须保留未确认，不得被更早的定稿掩盖。不能用固定两秒后返回失败代替协议判断。
- 意外断线清空旧译音并隔离失效代次，恢复只发新声音；发送前丢弃早于恢复切点或超过 750 ms 的排队包，单批不超过 500 ms。缺口样本数、采集区间和连接代次须可对账，不能以补传形成持续延迟。正常结束先排空已有发送任务，再结束云端输入。
- 百炼两种 Translate 输出均可通过 `bailianTransport` 选择 `websocket`（PCM16）或 `webrtc`（原生 Opus）；未配置时保留既有 WebRTC 兼容行为，不因模式静音而改成请求译音。检测策略由 `bailianTurnDetection` 决定。默认 `auto`：书面同译和带译音同传均使用 `server_vad`；只有显式配置 `speaker_detection` 时才使用它，threshold 固定 0.5。必须记录实际 transport、配置策略和服务回显检测方式；不能把 `auto` 发给服务。Google Transcribe 使用 WebSocket。原生输入设备只消费既有 PCM，不打开第二个麦克风或扬声器，禁止叠加网络 SDK 的降噪、回声消除与自动增益。发送编码参数在 `session.updated` 前保持 inactive。
- 译音播放使用持续的 `AVAudioUnitTimePitch`（pitch=0）及独立双水位调速控制，默认 1–1.5 倍；清空、重连、切模式时递增播放代次并 reset DSP，旧回调不能扣减新队列。`playback.catch_up` 记录速度、目标、库存、样本数与阈值。原始译音必须先归档，收包不能等待播放队列消费；超过显式缓冲安全上限必须报错并留存原音，不能把丢音当追赶。旧 5 秒清空停播策略不适用于 WebSocket 成批返回。
- `uploaded.wav` 保存客户端接受的 PCM；`webrtc-input-observed.wav` 保存送入编码器的有效输入样本，均不是服务器解码回传。`translated.wav` 保存收到的译音。验收同时检查输入逐字节一致、原生时钟 underflow、队列缺口、字幕时效与内容；不能只检查本地 send 返回。

- 收到百炼 `session.finished` 后先记录 `playout.draining`，继续接收尚在传输的译音；用单调时钟等待最多三十秒，实际静音尾部到达后才结束。协议确认与本地译音排空分别记账；超时不能标记 `playout.drained` 或假称完整。
- 百炼 LiveTranslate 不设置没有官方依据的九分钟主动轮换或课堂总时长上限；当前官方模型卡、接入与事件文档未查到明确的连接墙钟时长上限，不能借用 Omni 的 120 分钟或把上下文 token 长度换成连接寿命。`connection.rotation_policy` 记录实际策略；真实断线仍按既有缺口隔离与恢复规则处理。Google 原有轮换策略独立保留。十／二十分钟长测必须检查 connection_epoch，不能把多次短连接当作同一连接长上下文测试。

## 界面约定

- 正式发布只有主工程 `dist/LiveCaption.app`，桌面 `LiveCaption.app` 固定指向它；SaT、WhisperKit 等功能必须整合到同一个包。版本只改 `Resources/Info.plist`，build 使用递增整数。通过 `bash scripts/build.sh`／`scripts/release.py` 串行检查和发布，发布记录以 `Releases/current.json` 为准。独立开发显式设置 `LIVECAPTION_APP_PATH` 输出验证包，不能覆盖正式路径或改桌面入口；不得从旧实验工作副本直接交付。详细流程见 `Documentation/版本管理与发布.md`。

- 菜单栏是快捷控制；完整设置只由一个独立原生窗口承接，浮窗与迷你条均有显式入口。
- “后台整理字幕”开关及 SaT 参数都绑定实际运行配置并自动保存，不提供保存按钮或其他整理引擎。关闭立即取消 SaT，按服务器 VAD 语段及服务明确的中英关联显示，不按句号或长度再切。旧配置迁移 SaT，不读取或调用 JEV／聊天整理地址与凭据。文件写入按修订号排序，旧保存不得重新开启整理。开关、参数、取消和保存结果写入日志。
- “收起字幕”切换为可交互的迷你控制条；“隐藏到菜单栏”隐藏浮窗；二者不改变录制状态或日志生命周期。
- 完整字幕窗穿透时，独立控制条必须保持可点击，提供恢复操作、收起与设置入口；迷你条始终可点击，重启关闭穿透，菜单栏可恢复操作。
- 模式面向用户分为“原文转写 / 书面同译 / 同声传译”，映射既有 Pipeline / OutputMode，不新增云端线路。
- 书面同译必须在服务端只请求文字，不得生成译音后静音或丢弃。百炼使用 `output_modalities: ["text"]` 且不提交音色设置；Google 当前翻译适配器仅支持语音输出，因此仅文字配置在连接前拒绝。服务配置日志区分是否请求译音，不给纯文字会话虚报译音采样率。

- 内部按同一连接代次内明确的供应商原译文关联配对，不能按到达顺序硬配。SaT 是唯一整理路线，临时文字先连续显示，双语等待两轨定稿，仅在明确关联的服务组之间选择段落边界。无关联译文单独保留，不伪造配对；两轨正文保持逐字节保真。关闭时直接显示服务组，一组多句仍保留为同一段。
- 动态字幕通过右键复制本段原文或译文；不在持续变化的字幕 Text 上启用 SwiftUI SelectionOverlay。整理结果使用任务独立的显示标识，投影冲突时记录原因并回退原始字幕，不把冲突标识交给 ForEach。
- SaT 输入、模型概率、选择边界和字节校验写入 reflow-decisions.jsonl，events.jsonl 保留同名事件及索引。caption.presentation.changed 记录启用时 SaT 段落、关闭时 provider_groups 的原始显示边界与正文保真。
- SaT 合并等待默认 400 ms，同时仅一个任务；新增正式前缀才进入本机推理，不按八秒计时或临时标点触发。每次保留有限上下文处理新定稿文字；过期修订、连接代次和配置变化取消任务，失败保留完整原文。供应商收尾完成后有界等待整理及审计写入，再关闭日志。
- 实际语音线路验收使用可追溯的真人录音与参考文本，单次按真实时间输入；不以合成语音或循环短音频代表课堂效果。当前可复现入口为 scripts/verify-human-app.sh，样本为 LibriSpeech 的连续七段真人朗读。
- 界面稳定性验收必须全程挂载真实浮窗，包含连续文字更新、后台整理和 10 Hz 音量刷新；使用独立进程检查主线程心跳、保存 CPU／内存与超时采样。结束后才创建截图窗口，或仅检查分段数和正文保真，均不能证明实时界面未卡死。文件输入仍不代表物理麦克风采集。
- 实时延迟验收须用长录音检查累积滞后，分别记录采集到提交、原生队列、服务事件的音频时钟滞后、整理耗时和界面响应。`scripts/analyze-caption-latency.py` 按连接代次校准 RTP 时钟，不能把麦克风初始化后的第一帧当作已经运行的媒体轨起点；缺少服务时间戳不算零延迟。真人文件验收的服务事件滞后门槛为 5 秒，超限即失败；这是检测门槛，不是逐词延迟或服务 SLA。收尾、字节保真或首段较快不能替代此检查。
- 同音频修复验收用 `LIVECAPTION_LATENCY_REFERENCE` 指定健康完整的参考会话，运行 `scripts/compare-caption-progress.py` 检查 interim 原文进度；音频 PCM 必须逐字节一致、单次连接、匹配覆盖至少 60%，相对基线额外延迟 p95 不超过 2 秒、最大不超过 5 秒，末四分之一与首四分之一的中位差不超过 2 秒。最终全文替换须保留未改词的首次可见时间，不能把整段定稿时间冒充所有词的到达时间。该检查是相对参考进度，不是强制音频逐词对齐；换音源和已知断线回归分别报告。

- SaT 是唯一字幕整理路线；旧引擎字段只用于兼容读取，加载后固定为 `sat`。在设置的“本地模型”下载完整环境，或由开发者运行 `scripts/setup-sat.sh`；独立 Python、固定依赖、模型和分词器验证完成后，由持久 Python worker 的 ONNX CPU 离线推理执行，线程数限制为二。Swift 使用专用队列读写 worker，取消与超时终止对应进程；不能在主线程等待模型加载。`caption.sat.*` 将窗口、关联边界、两轨概率、阈值、采用／保留理由、加载和推理耗时写入现有分段审计日志。每次模型处理约一万字符，单个超大双语关联组保留完整并继续后续组，不设课堂总时长上限。final 修订只撤回受影响段落，普通 draft 追加不得撤回已固定前文；停止／换线路的旧结果不得跨代次应用。
