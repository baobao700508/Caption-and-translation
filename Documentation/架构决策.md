# 架构与构建约束

应用使用 SwiftPM 管理 Swift 源码和 C/C++ 桥接，由脚本构造包含隐私说明、资源和签名的原生 `.app`。录制应运行打包后的应用；直接运行不带 Info.plist 的可执行文件不是支持的录制入口。

麦克风使用 Apple Voice Processing；系统声音使用独立的 WebRTC Noise Suppression。采用 freedesktop 的 WebRTC Audio Processing 2.1 稳定分发包，固定归档 SHA256 和 Abseil 源码、补丁校验。该分发将 APM 从完整 WebRTC 网络栈中独立出来，可用 Meson/Ninja 静态构建，便于将 Swift 产品的依赖控制在音频处理模块。C 桥接只暴露生命周期、固定帧处理和原子环形缓冲。

实时音频回调只进行有界复制、声道合并和原子索引操作。HAL 设备创建与销毁在专用串行管理队列执行；需要等待系统授权时，菜单栏和浮窗仍能响应。文件读取、日志目录创建及崩溃恢复均在主线程之外执行。文件访问不发生在 SwiftUI 应用的静态初始化阶段。

音频生产与网络发送通过容量为两秒的 `AudioPacketQueue` 解耦，AsyncStream 只作唤醒信号；发送器立即取出数据，单批最多合并 500 ms；开始发送前丢弃已排队超过 750 ms 的包，不能用无限缓存掩盖延迟。Google 保留带五秒写入截止时间的 WebSocket。百炼两种 Translate 输出共用原生 WebRTC／Opus，经 DataChannel 交换模型事件，经媒体轨发送音频。虚拟音频设备消费既有 16 kHz PCM，不开启第二套硬件采集；200 ms 起始缓冲吸收 100 ms 前端回调和线程调度抖动，原生输入缓存有界，合并大包分段交付，尾部不足 10 ms 只补齐编码帧，不丢弃有效样本。会话配置确认前禁用 RTP encoding；不能只静音 track，因为静音包也可能让服务端提前进入 started 状态。`bailianTurnDetection` 默认使用本机策略 `auto`：书面同译选择 `server_vad`，带译音的同声传译保留 `speaker_detection`（固定 threshold 0.5）；显式指定两种方式仍受支持。配置策略和实际检测方式分别记录，按实际方式核验服务回显的检测方式、阈值、模型、目标语言、格式和输出模态，不能把 `auto` 发给服务。云端语段可持续较长时间，实时文字先显示、后台重排按已有标点前缀工作。`session.finished` 和译音排空分开记录，译音尾部最多等待三十秒，使用单调时钟，排空超时如实标为不完整。

日志 writer 为独立 actor，服务端临时文字即写 JSONL；Markdown 是可修订投影。窗口生命周期不拥有音频或连接。重连及模型切换沿用用户会话，旧连接迟到结果按其原始 epoch 和模型归属写入。保存客户端输入、原生编码器输入和收到的译音；编码器输入对照不包含启动空闲帧与尾部补零，尾部补零量另有计数。回放验证要求输入逐字节一致、有效样本全部消费、underflow 为零和正常收尾，不把 SDK 接受输入等同于远端消费确认。

WebRTC 进入 disconnected 后给予两秒恢复宽限，持续断开则重建连接；恢复为 connected/completed 会使旧计时器失效。失效代次立即停止接收新输入并清空播放队列，新会话配置就绪时建立恢复切点，早于切点开始采集的包全部丢弃，不携带恢复句柄重放旧上下文。旧代次迟到的字幕保留原日志归属，不覆盖当前屏幕；旧译音不再进入播放队列。`input.discarded` 记录被丢弃的样本数和采集区间，重连后的第一包成功时生成可读缺口摘要。

正常停止先结束采集并排空发送任务，再发送供应商结束输入事件；不能先取消正在写入的任务，因为取消 URLSession WebSocket 写入会关闭底层连接。排空最多等待八秒，超时明确记缺口并关闭连接。Google Transcribe 以 `audioStreamEnd` 促成最终 `inputTranscription`，最多等待十秒，仍只有临时结果或发生传输错误时保留未确认状态。`connection.final_finish` 表示最后连接的收尾结果，整场曾发生的缺口不因最后连接收尾成功而消失。

日志恢复只处理最近的未结束会话，拒绝修复仍有活动写入进程的目录。恢复仅重放完整事件行；尾部半行单独保全，再将末段标记为未确认。恢复路径限制在所选日志根目录之内。

本机未配置可用代码签名身份，开发包采用 ad-hoc 签名。重新构建后代码身份可能变化，macOS 可能再次要求首次文件或音频录制授权。对外分发需要独立完成 Developer ID 签名、公证和目标系统验收；运行时无需用户安装降噪库或构建工具。

正式应用链接固定版本 WebRTC M155 的 macOS framework；依赖归档的地址和 SHA256 由 `scripts/setup-webrtc.sh` 固定。`RTCAudioDevice.h` 来自同版本 SDK 的公开协议声明；macOS 分发未附带该头文件，但 factory 的公开自定义设备入口和二进制实现可用。原生设备关闭额外 APM，通过同一专用线程按 10 ms 交付音频，不依赖网页自动播放或可见窗口。WebRTC BSD 许可随应用打包。

`Experiments/RealtimeTransports/` 内的 AOQ、Network.framework 和 WebKit 实现仅用于有限文件回放对照，不自动用于正常记录。AOQ 的本地提交成功不是远端消费确认，SDK 推流观察轨也不是服务器解码录音。WebKit 后台音频上下文在本机被挂起，因此不能作为常驻后台方案。
