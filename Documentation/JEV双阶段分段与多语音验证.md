# JEV 双阶段分段与多语音验证

LiveCaption 0.1.6（build 7）支持 JEV 两阶段后台分段。桌面配置启用 `engine: jev`、`typesafe/jev-1.14`、`bc-v5` 提示词。阅读目标是完整意思块 B，允许连贯大段 C，不按短分句 A 强制拆分。聊天模型的地址、模型和凭据独立保留，可以在设置中切换。

实际分块、不同提示词的对照、录音、上传轨和逐题判断可从[可展开的实测报告](../TestResults/jev-two-stage-20261021/report.html)查看；[机器可读审计](../TestResults/jev-two-stage-20261021/audit.json)与[交付指纹](../TestResults/jev-two-stage-20261021/delivery.json)提供验收数据和源码／可执行文件 SHA-256。

## 两次请求的分工

程序先在两条完整文字轨道上机械标记句末、逗号、分号和换行等候选位置。缩写和小数受到基本保护；开引号、开括号跟随下一段文字，闭引号保留在原段。候选小片不是最终显示段落，正文始终从原始字片中切取。

第一轮把候选问题一起提交给 Decisions API，使用 `Choice` 匹配英文终点与中文终点。问题明确展示切点两侧的实际意思，完整原译文仍在状态中。不同句数、正常意译和块内语序变化均允许；内部颠倒导致没有连续对应前缀时应选 `none`。不按到达顺序、句数或位置比例硬配。低把握、未知选项和选项／分布矛盾有独立诊断。

第二轮把可能形成的实际双语块一起提交。每块使用 `Noul` 检查范围含义对应、前块完整及后文不悬空，用 `Score` 区分未完、合并更自然、完整意思结束和小话题结束。每题直接携带待判断的实际文字，减少相似候选范围之间的混淆。它不要求逐词翻译一致，也不因故事、人物或主题继续出现而必须把全文合并。

程序在候选图中选择中英顺序均向前的路径；允许跳过若干位置，形成较大块。每增加一个切点有代价，分块数本身不构成奖励。窗口尾部始终保留，可继续接续，并不因为显示出来就被宣称为语义确认。候选或请求预算超限时保留整块并记录原因，不截断正文或偷偷丢弃候选。

当前试验门槛为对应概率 0.80、完整性概率 0.75、Score 中完整意思／小话题两级合计概率 0.65、额外切点代价 1.5。它们是应用规则，不是模型准确率，也不是官方推荐值。纯原文转写没有双语匹配，跳过第一轮，只运行第二轮的适用问题。

## 实时更新与失败处理

原始字幕及课堂日志先输出，不等待 JEV。完成段合并等待默认 400 ms，任务启动间隔至少 1.5 秒，同时仅运行一个整理任务。追加文字合并等待，避免不断取消两阶段调用；原文字节修订、连接代次变化或配置变化才让旧结果失效。

长语段按至少 8 秒间隔检查带句末标点的可用前缀，不是每 8 秒强制换段。最近一个已整理块允许接续，较早块固定。采用前检查输入范围仍有效、两轨切点有序、完整覆盖，并验证拼接后的 UTF-8 字节分别与原始轨道完全一致。

JEV 单次请求超时为 6 秒；重试次数独立限定为 0 或 1，正常双语任务为两次请求，发生重试时可能再次运行两阶段。停止时在供应商末段处理后有界等待整理与审计写入，再关闭会话日志。网络、概率结构或日志失败均保留已有完整字幕。

## 可观察的判断日志

会话目录的 `reflow-decisions.jsonl` 在运行中可追读。它包含课堂文字，沿用本地会话目录的私有权限。日志不保存 API Key、鉴权头或配置文件。

| 事件 | 记录内容 |
| --- | --- |
| `caption.reflow.started` | job、连接上下文、尝试次数、最终段／稳定前缀触发原因、模型及输入范围 |
| `caption.reflow.candidates` | 两条完整文字、候选位置、提示词版本、全部采用门槛 |
| `caption.reflow.request` | 阶段、完整问题、所有选项／等级／条件、请求字节数与问题数量 |
| `caption.reflow.response` | 实际返回模型、所有答案与概率分布、置信度、等级、用量及耗时 |
| `caption.reflow.alignments` | 每个对应选项及采用／拒绝原因，包括 `none`、低概率与分布矛盾 |
| `caption.reflow.span_rejected` | 交叉、重复位置或有限搜索预算导致的范围拒绝 |
| `caption.reflow.selection` | 每块检查值、评分、路径收益、是否被选中、拒绝原因、最终切点及临时尾部标记 |
| `caption.reflow.validated` | 应用前的完整行与逐字节保真确认 |
| `caption.reflow.failed` / `discarded` / `retained` | 请求失败、修订失效、取消、停止超时与保留整块的原因 |

`events.jsonl` 保存同名事件、`job_id` 和 `trace_sequence`，指向详细日志；`caption-layout.json` 保存派生排版。`transcript.md` 与 `live.md` 继续表达原始识别／翻译修订，不被分段模型改写。

## 提示词对照与样本边界

开发文本包括用户选择 B／C 的虚构排课说明、逆序因果和 ASR 标点碎片；语音开发资料来自说话人 1089、6930。不同提示词的完整请求和失败结果分别保留，不能用最终成功覆盖早期失败。

| 开发条件 | 观察结果 |
| --- | --- |
| 基础 v1，完整排课例文 | 2 块，后半段过长 |
| v2，强调完整意思和独立判断 | 1 块，仍过度合并 |
| v3／v4，相邻语义及候选结构对照 | 部分短样本改善；长样本仍有低把握、请求预算或选项分布问题，失败保留 |
| v5，逐题明确绑定实际待判断文字 | 相同排课例文 5 块；两份固定真人字幕分别 2 块和 3 块；全部成功输出保持两轨字节一致 |

v5 的提示词源码指纹、门槛和开发／留出说话人名单在[冻结计划](../TestResults/jev-two-stage-20261021/frozen-evaluation-plan.json)中。提示词及门槛冻结后，用 1221、1320 两位未参与提示词调整的说话人测试，未再根据其结果修改提示词。

两份虚构留出文本覆盖一对多、多对一、逆序、引号、缩写和小数。首轮引号样本发现了通用字片归属问题，原始结果保留；修正后作为回归样本复测，不能再把该复测视为完全未见数据。修正后的两份文本分别输出 3 块、2 块，列明的五个不可拆范围均完整保留。这些约束和字节检查不构成完整语义准确率。

## 真人语音应用验证

全部使用 [OpenSLR LibriSpeech test-clean](https://www.openslr.org/12/) 真人录音，CC BY 4.0，16 kHz 单声道 PCM，按真实时间有限输入，无 TTS、循环或硬件采集。各录音 provenance 保存来源、所选原始片段、参考文本、时长及 PCM SHA-256。1089 和 1221 为各自章节连续五条原始录音；6930 为既有连续七条；1320 为明确列出的三条不同原始录音。

| 说话人 | 用途／时长 | 冻结 v5 的书面同译结果 | 运行中整理次数 | 最终双语块 |
| --- | --- | --- | --- | --- |
| 1089 | 开发，28.230 秒 | 完整输入、收尾确认、两轨字节一致 | 4 | 4 |
| 6930 | 开发，76.145 秒 | 完整输入、收尾确认、两轨字节一致 | 9 | 6 |
| 1320 | 留出，19.100 秒 | 完整输入、收尾确认、两轨字节一致 | 3 | 2 |
| 1221 | 留出，55.135 秒 | 首轮失败保留；同录音复跑完整输入、收尾确认、两轨字节一致 | 复跑 6 | 复跑 2 |

成功书面同译运行中的单批后台整理约 0.65～1.49 秒。这是两阶段整理任务耗时，不是语音结束到字幕显示的端到端延迟。字幕先显示，模型只影响后续排版。

1221 首轮收到语音服务 `COMMON_ERROR: session does not exist`，64,560 个输入样本、约 4.035 秒被明确丢弃，收尾未确认。关闭 JEV 的同录音对照完整通过，随后开启冻结 v5 的复跑也完整通过。现象尚未稳定复现，原因未定；不能依据这些有限运行断言由 JEV 导致或已永久消除。

同声传译模式另用 1320 的 19.1 秒录音验证：完整输入、收尾确认、3 次整理，译音接收与存档保留。文件验证不播放物理扬声器，不代表远场麦克风、声学回授或整堂课验证。

离线回归为 **43 项、0 失败**，覆盖两阶段、逆序、无对应、非法答案拒绝、字节保真、日志失败、配置兼容、追加合并及原有音频／协议行为。最终原生验证为 **18 项通过**，覆盖先显示、先记日志、真实 JEV 整理、两轨保真、原文／译文视图、同传共用视图、单轨不生成译文和设置保存。

观察上，v5 已减少不必要的小切片并保留复杂逆序范围，但文学录音和引号较多的文本仍可能合成偏大的段落。后续质量判断应看报告中的实际双语块及逐题证据，继续使用新说话人、新内容验证；不能仅凭分块数判断更好，也不能把某一轮大段输出等同于模型不可用。

## 复现入口与配置

- `scripts/check.sh`：离线回归。
- `scripts/prepare-jev-voices.py`：准备有来源和开发／留出标记的不同真人录音。
- `LiveCaptionReflowProbe 配置.json 样本.json 输出目录`：通过生产客户端对固定双语字幕执行真实两阶段调用。
- `scripts/verify-human-app.sh subtitles 配置.json`：真实应用书面同译；`LIVECAPTION_HUMAN_FIXTURE` 选择不同录音，`speech` 选择同传模式。
- `scripts/verify-jev-caption.sh 配置.json 样本.json 输出目录`：原生字幕与设置验证。
- `scripts/analyze-jev-reflow.py TestResults/jev-two-stage-20261021`：重算审计与 HTML 对照。

`Resources/Configuration.example.json` 提供可填写配置；私有凭据只进入用户配置文件或 Keychain。设置 → 字幕与外观 → 模型辅助分段，可以选择 JEV 两阶段判断及提示词版本。旧聊天配置保留，切换方式即可回到原线路。

源码入口为 `JevCaptionReflow.swift`、`CaptionReflow.swift`、`SessionLog.swift` 与 `AppSession.swift`。当前 LiveCaption 子目录没有独立 `.git`，父目录 Git 未修改或提交；交付是该目录源码、可执行应用及指纹清单，不冒称已有子项目分支提交。

类型定义参见 [Choice](https://docs.typesafe.ai/primitives/choice)、[Noul](https://docs.typesafe.ai/primitives/noul)、[Score](https://docs.typesafe.ai/primitives/score)。这些定义支持接口设计，不替代上述应用测试。
