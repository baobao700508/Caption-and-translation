# SaT 本地段落整理

SaT 是当前唯一的字幕整理方式。默认模型为 `sat-3l`，使用本机 ONNX Runtime CPU 推理；识别、翻译和译音播放仍走原有线路。SaT 不调用 JEV 或聊天服务，也不需要云端 API Key。

## 文字如何显示

原文转写的 Google、WhisperKit，以及纯文字翻译、带译音翻译，共用同一条 SaT 后处理路径。

1. 收到 draft 时立即显示，连续进入一个待整理尾段，日志也立即记录。
2. 只把从前向后连续、已经 final 的文字交给 SaT。双语必须等原文和明确关联的译文都 final；百炼的 `response.text.done`／`response.audio_transcript.done` 仍不能单独当作该响应最终完成，适配器等待成功的 `response.done`。
3. 本机模型给出原始字符后的换段分数，程序只选择原文字片的边界，不让模型改写正文。按分数和最短长度筛选，不设置按段落字数强制切分的兜底。文字再长，只要模型分数没有达到阈值，就不在该点切开。双语仅使用明确关联组的边界。
4. 选择出的前段固定，末段继续接收新文字。普通 draft 追加不撤回固定段落；final 被更正时，仅从受影响的位置开始重新处理。回看时沿用现有冻结显示行为。

这不是逐音频包推理。多次更新先合并，再处理约一万字符的有限窗口，并携带前两个处理单元作为上下文。不会每次把整节课重新送入模型，也没有九分钟课堂总时长限制。单个超过本地处理上限的双语服务关联组保留完整，后面的组继续处理。

## 中英文如何对应

SaT 不负责跨语言语义对齐。双语换段只能发生在供应商明确关联的原文／译文组之间：原文可以是一句，译文可以是两句，也可以在组内改变语序。整个关联组一起保留，不按字符比例、到达顺序或句子数量配对。

因此，一个服务组特别长时，这版 SaT 不能把它内部的中英文再对应切开；它会保留较大的双语块。真正没有关联标识的译文继续单独显示警示，不冒充已经配对。

单语没有跨语言对应问题，可以直接在模型支持的原文字片边界换段。

## 本地环境与设置

本机环境已准备在：

`~/Library/Application Support/LiveCaption/SaT/runtime/bin/python3`

其他机器可在项目目录运行 `bash scripts/setup-sat.sh`。该脚本安装固定版本的 `wtpsplit[onnx-cpu]`；模型首次使用时从 Hugging Face 下载，此后使用本地缓存。应用包携带 worker 和许可证，Python 运行环境保留在用户目录。

在“字幕与外观”里启用后台整理；SaT 参数自动保存。选择和保存 SaT 时不会读取或更新整理服务的钥匙串密钥；在线识别／翻译自身需要的凭据仍由各自线路管理。

默认设置：

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 模型 | `sat-3l` | 本地推理模型 |
| 换段阈值 | 0.20 | 候选边界两轨分数的较大值须达到该值；不是语义正确率 |
| 最短段落 | 120 个字符 | 换段前后均须满足；双语按原文和译文字符合计，减少碎段 |
| 单次超时 | 120 秒 | 包括首次加载；超时保留全文，不阻塞字幕或录音 |
| 推理线程 | 2 | 限制 CPU 并行度 |

建议阈值低于 0.50。超过 0.50 时，模型分数可能一直达不到要求，导致字幕持续不分段；设置页面会显示警告，不会自动降低阈值或按字数强切。已有配置中明确选择的阈值继续保留，新配置默认 0.20。

可选模型还包括 `sat-3l-no-limited-lookahead`、`sat-3l-sm` 和 `sat-12l`。这次实际验证的是默认 `sat-3l`；不能把其他模型列在设置里当作已经完成各自实测。

## 观察实际判断

会话的 `reflow-decisions.jsonl` 保存：

- `caption.sat.request`：处理的原译文窗口、模型、阈值及可用关联边界。
- `caption.sat.selection`：两轨各边界分数、采用或拒绝原因、最终边界、模型加载与推理耗时。`selected` 表示分数达到阈值并通过最短长度限制；`below_paragraph_threshold` 表示分数不足。
- `caption.sat.retained`：超大关联组保留完整的原因。
- `caption.sat.revision`：更正造成的段落失效和保留数量。
- `caption.presentation.changed`：实际可见段落及原始服务组的标识和数量、正文逐字节检查。

未找到段界时，界面显示“SaT 已检查，等待合适段界”；完成推理不代表已经切出了新段。现有 `caption.reflow.*` 事件同时记录启动、校验、失败和过期结果。日志写入失败时不继续调用模型；推理失败、配置无效或响应过期都保留完整文字。

## 验证范围

离线检查覆盖四条线路的 draft／final、迟到译文、修订、代次切换、日志失败和逐字节保真，并实际调用本机 SaT 检查中英文及 Unicode。

真实历史文字事件通过生产协调器加速回放，分别检查 Google、WhisperKit 和两种翻译模式；原生 App 验证字幕视图、设置、保存与截图。这些验证没有重新采音或调用云端翻译，不能据此宣称识别、翻译或译音到达延迟改善，也不能用段落数量代替语义质量评价。
